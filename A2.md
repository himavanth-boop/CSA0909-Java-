A2.1 – Predict the Cost (2 Marks)
The attendance log has a size of 50 MB.
When using FileInputStream.read() one byte at a time, the program makes approximately 52,428,800 read calls (assuming 1 MB = 1,048,576 bytes).
Reasons for slow performance:
•	Each read() operation reads only one byte.
•	A very large number of read operations are required.
•	Repeated method calls and I/O overhead reduce performance.
•	The program spends more time reading data than processing it.
A2.2 – Redesign Using Buffering (2 Marks)
Use BufferedInputStream to read the file in buffered chunks instead of reading one byte at a time.
Java Code:
import java.io.*;

public class BufferedLineCounter {
    public static void main(String[] args) throws IOException {

        int lines = 0;

        try (BufferedInputStream bis =
                 new BufferedInputStream(
                     new FileInputStream("attendance.log"))) {

            int data;

            while ((data = bis.read()) != -1) {
                if (data == '\n') {
                    lines++;
                }
            }
        }

        System.out.println("Total lines: " + lines);
    }
}
Explanation:
•	FileInputStream reads bytes from the file.
•	BufferedInputStream maintains an internal buffer.
•	Data is fetched in larger blocks instead of requiring an operating-system read for every byte.
•	This reduces operating-system calls and improves reading performance.
A2.3 – When Buffering Does Not Help (1 Mark)
Buffering gives little or no benefit when the data is already available in memory or when the program reads only a very small file once. In such situations, the overhead of creating and managing a buffer may provide no noticeable performance improvement.
Alternative Concept and Complexity Analysis – Files.readAllLines()
If the complete file is read using Files.readAllLines(), the program loads all lines into a list before counting them.
Java Code:
import java.nio.file.*;
import java.io.IOException;
import java.util.List;

public class ReadAllLinesCounter {
    public static void main(String[] args) throws IOException {

        List<String> lines =
            Files.readAllLines(Path.of("attendance.log"));

        System.out.println("Total lines: " + lines.size());
    }
}
Complexity Analysis:
Approach	Time Complexity	Space Complexity
Buffered stream	O(n)	O(b)
Files.readAllLines()	O(n)	O(n)
Where:
•	n = file size or total input data.
•	b = buffer size.
Comparison:
•	Buffered streams process data in smaller chunks and use limited memory.
•	Files.readAllLines() loads the entire file into memory.
•	For a 50 MB file, readAllLines() may require considerably more than 50 MB because of String and List object overhead.
When to use:
•	Buffered streams are suitable for large files and memory-efficient processing.
•	Files.readAllLines() is suitable for small files that can comfortably fit in memory and when all lines are needed together.
Conclusion
Buffered streams are more efficient for processing large attendance logs because they reduce repeated I/O operations and use less memory than loading the entire file at once.
